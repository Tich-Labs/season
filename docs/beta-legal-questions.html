A. Hosting and access

No.QuestionDrafted answer
1 Which hosting provider and database do we use for the Beta, and in which server region is the data stored? Hosting: Render (render.com) — platform-as-a-service. App runs at seasonv2.onrender.com.

Database: PostgreSQL (Render-managed), database season, user season, free plan. Rails is configured for PostgreSQL only (config/database.yml, adapter postgresql).

Region: Frankfurt (EU Central) for both the web service and the database — data is stored inside the EU, so no additional transfer safeguards (Standard Contractual Clauses) are needed for the hosting location itself.

confirmed source: Render dashboard (service + database region) · render.yaml, config/database.yml
2 Who has access to the production database? Please list roles (or names) and the number of people. The codebase defines an application admin role (User#admin?, routes under /admin/*, separate /admin/login), but production database access is not enumerable from the repo — it is granted via the Render Postgres connection string (DATABASE_URL env var) and the Render dashboard.

Known so far: the Render account is under Season UG; admin access via naijeria@season.vision (role: Admin).

needs your input — confirm whether that is the only account, and the full list of roles/names + count of people with DB access.

Extra facts the drafts can rely on (already confirmable)

  • Passwords are stored only as a bcrypt hash (encrypted_password column, Devise). confirmed
  • Encryption in transit: TLS is enforced app-wide with HSTS (config.force_ssl = true, config.assume_ssl = true). confirmed
  • At rest: the beta disclosure already states entries are "not yet end-to-end encrypted on our server". The GDPR audit additionally flags database-level encryption not enabled and OAuth tokens stored unencrypted — both affect the "How your data is stored and protected" section. needs confirmation
  • Retention: DataRetentionJob (runs daily at 2am) deletes cycle/symptom data after 3 years, calendar/superpower entries after 1 year, and consent records after 3 years; account data is deleted within 30 days of account deletion. Combined with the already-decided "technical logs 30 days / feedback up to 12 months after the Beta". confirmed
  • Additional processors: email via Resend, error tracking via Sentry (both in render.yaml env). The GDPR audit notes DPAs with these are outstanding. needs confirmation
