## ✅ Fixed, 3 Sep 2026

| Card | Priority | Fix |
|---|---|---|
| Code Popup pops up randomly after setting or editing appointments | P1 | Real bug, confirmed: `session[:pin_verified_at]` was written once at login/PIN-entry and never refreshed, so `PinProtection::PIN_TIMEOUT` (5 min) silently behaved as a flat "locked exactly 5 minutes after login" timer instead of the *idle* timeout it's documented and designed as (`app_lock_controller.js` only forces a re-check after real backgrounding). Multi-step appointment creation (category/location/guests/notes/reminder/repeat sub-modals) is one of the few flows long enough to routinely cross 5 minutes of continuous, non-idle use — so saving or editing one would frequently hit an already-"expired" timeout on the very next request and throw up the PIN modal, reading as random. Fixed by making `require_pin_unlock` a sliding window — any request that still passes refreshes `pin_verified_at`, so continuous activity keeps a user unlocked indefinitely while genuine idle time still locks exactly as designed. Tests: `spec/requests/pin_protection_spec.rb`, 2 examples. |
